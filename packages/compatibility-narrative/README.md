# `@inyeon/compatibility-narrative`

Deterministic, client-side presentation boundary for compatibility evidence.

The public composer accepts only a validated compatibility snapshot and closed presentation enums. It performs no calculation, freeform interpolation, network request, storage write, logging, clock read, random selection, or runtime model call. Output is plain structured text and is deeply frozen.

The checked-in `us-english-narrative-copy-v1` catalog intentionally contains zero relationship claim entries because INYEON currently has zero approved compatibility rules. Current product output therefore has:

- no relationship archetype or headline;
- empty `What clicks`, `Potential friction`, and `Why this?` sections;
- no personalized conversation question;
- an honest `no-approved-evidence` status;
- methodology, categorical evidence-availability, time-input, and entity-context limitations only.

Future relationship copy is default-deny. It requires a production-eligible approved snapshot, a definitive matched rule, safe categorical availability, an allowed copy key, an exactly bound reviewed catalog entry, and rule/evidence traceability. Candidate, not-matched, alternative, unavailable, suppressed, test-only, or unknown copy never becomes a claim.

Public copy is natural US English. Korean-rooted identity remains explicit, and any Korean script follows Hangul-first order such as `Korean Saju (사주, Four Pillars; 四柱)`. Hanja is secondary traditional detail, never the primary label.

`share` is only a reviewed short-copy variant. It removes birth-time precision and evidence references, but it is not the #43 share allowlist or serializer.
